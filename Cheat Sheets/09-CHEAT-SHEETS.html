One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Join types: the decision that changes everything

Join typeWhat it gives youPick it when
Entra registeredDevice identity for SSO and Conditional Access; no MDMPersonal BYOD; app protection only; no device control needed
Entra joinedCloud device identity plus Intune MDMCorporate device with no on-premises dependency
Entra hybrid joinedAD domain membership plus Entra identity and IntuneKerberos, on-premises shares, legacy apps, or Group Policy still needed
  • Check a device with dsregcmd /status: AzureAdJoined, DomainJoined, EnterpriseJoined.
  • Registered is identity only; joined is identity plus management; hybrid is both directories.
  • Hybrid join needs Entra Connect sync, a service connection point (SCP), and line of sight to a domain controller at join time.

Enrolment methods

MethodBest forWatch out
Automatic enrolment (MDM user scope)Entra joined devices at first sign-inNeeds licences and MDM scope set to All or a group
Windows AutopilotNew corporate hardware, zero touchThe hardware hash must be registered first
Bulk enrolment (provisioning package)Existing devices with no hashThe package carries a short-lived enrolment token
GPO automatic enrolmentHybrid joined domain devicesNeeds the GPO and a domain-joined device
Co-managementConfigMgr estates moving to IntuneWorkloads move one at a time
Manual (Access work or school)One-off or lab devicesNot a scale strategy
  • Enrolment restrictions: platform, minimum and maximum OS version, personally owned device block, and a per-user device limit (default 15).
  • Corporate identifiers and device categories support ownership reporting; they do not enrol anything.

Autopilot profiles

ModeUser at OOBEJoinsTypical use
User-drivenYes, signs inEntra joined or hybridStandard knowledge-worker laptop
Pre-provisioning (white glove)Technician first, user laterEntra joined or hybridIT prepares the device before shipping
Self-deployingNo userEntra joined onlyKiosk, signage, shared device
Device preparationYesEntra joined onlySimpler, newer user-driven flow
  • Every mode needs: registered hash, device in an assigned group, a profile, network, and an Intune licence.
  • Self-deploying needs TPM 2.0 and cannot use hybrid join. Pre-provisioning needs TPM 2.0 and wired or wireless network.
  • ESP stages: device preparation, device setup, account setup. Track required apps and block until installed.
  • Autopilot Reset removes user data and apps, keeps Autopilot registration and Intune enrolment, and returns to OOBE.
  • Troubleshoot: normal OOBE with no Autopilot screen means the hash or profile assignment is missing, not a profile setting.

Windows 365 and Azure Virtual Desktop

OptionWhat it isKey limits
Windows 365 BusinessCloud PC on a Microsoft-hosted networkNo Azure network connection, no hybrid join, small-tenant ceiling
Windows 365 EnterpriseCloud PC with provisioning policiesSupports ANC, hybrid join, custom images
Windows 365 FrontlineShared Cloud PCs for shift workersOne licence covers several users, not concurrent sessions
Windows 365 BootDevice boots straight into the Cloud PCWindows 11 endpoint, Entra joined
Azure Virtual DesktopYour own host pools in AzureYou manage images, hosts, scaling, and FSLogix
  • A Windows 365 Enterprise provisioning policy = image, network, region, join type, and assignment.
  • An ANC needs a virtual network, a subnet, and either domain join credentials or Entra join.
  • AVD objects: host pool (pooled or personal), application group, workspace, session hosts, scaling plan.
  • Multi-session Windows 11 Enterprise lets several users share a host; FSLogix containers roam profiles.

Upgrade and activation

  • Windows subscription activation: a Microsoft 365 E3/E5 licence steps Windows Pro up to Enterprise with no product key.
  • In-place upgrade keeps apps and files; use a feature update policy, or a task sequence when the upgrade needs custom steps.
  • Feature update policy targets a Windows version with a rollout date and a deadline.
  • Readiness: Endpoint analytics reports app and driver blockers before a Windows 11 rollout.
  • Provisioning packages (Windows Configuration Designer) can join, enrol, and apply a small set of settings; they are not a replacement for Autopilot profiles.

  • Suite features are per-user add-on licences; they are not included with Windows Pro.

Health and hygiene

  • Device check-in is roughly every 8 hours; Sync forces an immediate check.
  • Tenant status shows connector health; service health shows active incidents.
  • Audit logs record admin actions with actor and time; stream them with diagnostic settings for retention.
  • Device cleanup rules retire devices that have not checked in for a set period.
  • Diagnostic settings send logs to Log Analytics, Event Hubs, or a storage account.

Compliance versus configuration

QuestionCompliance policyConfiguration profile
What does it do?Evaluates and reports stateDelivers and enforces settings
Typical settingsBitLocker on, minimum OS, Defender onBitLocker cipher, update ring, firewall rule
ResultCompliant or not compliantApplied, error, or conflict
Feeds Conditional AccessYes, through the Entra device objectNo
Multiple policiesCumulative; the device must meet allConflicts when values differ
  • Compliance answers "is it allowed?"; configuration answers "what is set?".
  • Devices with no compliance policy follow the tenant setting, which defaults to compliant. Change it to not compliant before enforcing Conditional Access.

Compliance rules by platform

ControlWindowsiOS and Android
EncryptionRequire BitLockerRequire encryption

  • Machine risk score needs Defender for Endpoint onboarding; without it the signal is missing.

Compliance actions and timing

ActionEffect
Send email to end usersGuidance before enforcement
Mark device noncompliantChanges state after the schedule; this is the grace period
Remote lockLocks the device immediately
RetireRemoves company data and management
  • Actions run on a schedule; a one-day delay on Mark noncompliant is a one-day grace period.
  • State reaches Entra ID at check-in, so a recent fix may not show for a while. Sync first.
  • Retire is for BYOD departure; wipe is for reissue or compromise.

Conditional Access

Building blockExamples
AssignmentsUsers, groups, workload identities, directory roles
ConditionsUser risk, sign-in risk, device platform, location, client apps, device state
GrantBlock, MFA, compliant device, hybrid joined, app protection, approved client app, terms of use, authentication strength
SessionSign-in frequency, persistent browser, app enforced restrictions, continuous access evaluation
  • Grants in one policy combine with AND; use separate policies for OR.
  • Report-only evaluates and logs without enforcing; pilot there, then turn on.
  • Every design needs a cloud-only break-glass account excluded from all policies and monitored.
  • The app protection grant is the BYOD answer; compliant and hybrid joined grants need management.
  • Sign-in frequency is the fixed reauthentication interval.
  • Intune writes compliance to the Entra device object; Conditional Access reads it at sign-in.

Defender stack

ControlWhat it does
Onboarding (EDR policy)Sends device signals to Defender for Endpoint
Antivirus policyScan schedule, exclusions, cloud protection, intelligence updates
ASR rulesAudit, warn, or block risky behaviours
EDR block modeBlocks malicious behaviour when third-party AV is primary
Tamper protectionStops local changes to Defender settings
Live responseRemote shell for investigation and containment
Security baselineRecommended configuration across many controls
  • Pilot ASR in audit, review events, then block; scope an exception to the affected group.
  • Defender portal visibility is Defender RBAC plus device groups, not Intune RBAC.
  • Plan 2 adds EDR, automated investigation, advanced hunting, and live response.

BitLocker

  • Silent enablement needs a disk encryption policy plus a ready TPM 2.0.
  • TPM plus PIN adds a pre-boot secret; TPM-only is transparent to the user.
  • Escrow recovery keys to Entra ID or AD before encryption runs.
  • Rotate the recovery key after exposure; retrieval needs the narrow Intune permission.
  • The Encryption report shows encryption and escrow state across devices.

LAPS and local privilege

ControlScope
Windows LAPSBuilt-in local administrator password, rotation, Entra or AD backup
Legacy LAPSMSI client-side extension, being retired
Local user group membershipAdds or removes members from Administrators and other groups
Endpoint Privilege ManagementJust-in-time elevation for a specific app
  • LAPS needs a supported Windows build and an existing local admin account named in the policy.
  • EPM keeps users standard and elevates the app, not the person.

Win32 mechanics

ElementPurpose
Install commandRuns the installer, for example msiexec /i app.msi /qn
Uninstall commandRemoves the app
Detection ruleProves the app is already installed
Requirement ruleGates whether the app is offered
Install contextSystem for HKLM and no-user installs, user for per-user
Return code0 success, 3010 soft reboot, 1641 hard reboot, 1618 retry, 1603 fatal
  • Detection is "is it there?"; requirement is "should it be there?".
  • Supersedence replaces an older version and can uninstall it; a dependency installs a prerequisite first.
  • ESP can block the desktop until required apps install; only required apps can be tracked.
  • Win32 logs: IntuneManagementExtension.log and AppWorkload.log on the device.

MAM versus MDM

CapabilityMAM (app protection)MDM (enrolment)
Device enrolmentNot requiredRequired
ProtectsData inside managed appsWhole-device configuration

  • App protection areas: data protection and access requirements (conditional launch). App configuration is a separate policy.
  • Conditional launch handles PIN, jailbreak or root, minimum OS, and threat level.
  • Multi-identity lets personal and work accounts coexist with protection on work only.

  • Selective wipe removes corporate data on BYOD; a full wipe is never the BYOD answer.

Update rings

SettingEffect
DeferralDelays updates by a number of days
DeadlineForces installation by a date
Grace periodPostponement allowed before the deadline
Active hoursPrevents restarts during working time
PauseTemporarily stops updates

  • One device, one update ring; two rings with different values create a conflict.
  • Feature update policies target a version with a rollout date and a deadline.

  • The Windows Update compliance report shows devices missing updates.

Administration hygiene

  • Audit logs answer "who changed what"; device telemetry does not.
  • Cleanup rules retire inactive devices; review stale records on a schedule.
  • Tenant status shows connector health; service health shows incidents.
  • Remote Help is attended support; lifecycle actions are separate.
  • Scope tags and RBAC limit what an admin can see and do.
